The bundle built from `5571813`, the 2026-10-14 tree — never tagged or
published. v68 (pre-launch cleanup) folded the unpublished 0.4.0 and
0.4.1 entries into it.

### Added

- **Network access control (NAC):** scoped port policies, an expiring
  MAC/OUI allowlist, MAC sightings and locator, rogue-device, MAC-move,
  port-overflow and spoof detection, plus review, reports and topology
  overlays. Separately gated shutdown and quarantine-VLAN actions require
  SNMPv3 authPriv, eligible devices and explicit administrator confirmation.
- **NAC ships off and dry-run is on.** Enabling detection starts in
  notify mode; neither enforcement action turns on by itself.
- **Support bundles:** a redacted ZIP from Settings → Support or the
  CLI, with health, preflight, settings posture, table counts, backup/drill
  history, integration summaries and sanitized logs. `nac.json` adds
  NAC posture and aggregate findings/actions without configs or credentials.
- **The warm standby kit is opt-in.** A primary Compose overlay and
  PostgreSQL 16 standby-host kit provide capped-WAL streaming replication,
  status/decrypt checks, lag/slot alerts and explicit manual promotion.
- Browser smoke coverage of every frontend route on the demo estate
  in English, Hebrew and Arabic, plus Hebrew phone-width screenshots.
- A release-generated 0.5.0 backup fixture, restored at migration head in CI.


- SSH host-key pinning for config pulls (`config_host_key_policy`:
  `tofu`, `strict`, `off`) with admin trust rulings in the review queue.
- Upgrade safety: the operator CLI (`python -m app.cli preflight`,
  `backup`, `migrate`, `drill`), a backup-guarded migrate on start,
  `upgrade.sh` in the offline bundle, and per-release backup fixtures.
- Curated compliance packs (Cisco IOS, MikroTik RouterOS, Check Point
  Gaia, FortiGate FortiOS), the `gaia` and `fortios` config drivers, and
  the compliance report.


- **Rack system** — racks as data with SVG elevations, a drag-and-drop editor, carriers and shelves, a device image library, bayed rack groups with capacity, power and weight, first-class devices with ports, cables and patch panels, faceted filters, and CSV/XLSX import and export for devices and racks.
- **Observed state** — secrets encrypted at rest, subnet semantics, ping/TCP/HTTP monitoring with notification channels, a review center, SNMP enrichment, traps, cable validation and inventory sync, rack audits by QR walk-up, a topology map, device templates, reports, the sources connector framework with its connector waves, docs and attachments, OIDC SSO and API tokens, 24 interface languages, entity families, NetBox import, dashboards, and the app-wide polish waves.
- **Loop-closing** — the Check Point runtime hop, notifications in every locale plus syslog/SIEM delivery, LDAP sign-in, TOTP MFA, maintenance windows, DNS PTR write-back, source-of-truth automation, the NetBox live source, and SSH config backup.
- **Premium** — config compliance on stored revisions, a self-service IP request portal, per-user notification preferences, capacity forecasting, scheduled restore drills, audit export, VLAN planning, the IPv6 observed-state tail, and device groups.
- **Experience** — a one-click demo estate with a spotlight tour and a provable purge, so a first install shows value in minutes.
- **Studios** — the Topology Studio (atlas, layers and lenses, whiteboard that commits through preview → apply) and the Design Studio (typed freestyle network designs with auto-legend, BOM, templates and an opt-in promote journey).
- **This release** — a single version source (`backend/app/version.py`), CI on every push and pull request, a tag-driven release workflow that drafts a GitHub release, and an offline install bundle (`lancompass-<version>-offline.tar.gz`) with the four images, a checksum-verifying `install.sh`, English and Hebrew install guides, a CycloneDX SBOM and a manifest. Compose services now carry `image:` names (`LANCOMPASS_IMAGE_PREFIX`, `LANCOMPASS_VERSION`) so a bundle starts with `docker compose up -d --no-build`; a source checkout still builds.

### Changed

- CI runs on pushes to `main` and pull requests targeting `main`,
  including browser smoke and warm standby checks. Feature-branch pushes
  do not duplicate their PR runs.
- **Node 22 or newer is required for source builds of the web image.**
  CI and the web Dockerfile use Node 22; the smoke harness uses its
  built-in WebSocket without adding dependencies.
- Docker Hub pulls authenticate when repository credentials are present;
  secretless PRs skip login and pull service images anonymously.


- The largest frontend surfaces are split into smaller modules with a
  size budget (`check:size`).


- **Rename** — the product is now LanCompass. The pre-rename environment variable names, the old session cookie, saved preferences and old backup files keep working; the Compose project name and volume names are unchanged.
- The web image installs with `npm ci` from `package-lock.json` instead of `npm install`.
- The backend test suite resets its database with one `DELETE`-based transaction instead of a `TRUNCATE` per test.

### Fixed

- Report links for Address status and Monitors now open the existing
  `/prefixes` and `/monitoring` routes. A guard checks every section link;
  the browser smoke allowlist is empty again.
- Backend tests close shared Redis and ARQ pools after every test,
  preventing cross-event-loop connection leaks.


- The backup download and the scheduled backup no longer crash when a
  prefix has DNS resolvers set (fixed after the 0.4.0 tag, first shipped
  here).
- The demo estate's hand-made compliance finding uses the `line_no` key
  the engine writes.

### Security

- Both compliance rule test-run endpoints require `config:read` to
  return matched config lines. Write-only tokens retain device verdicts
  but receive empty evidence and `lines_hidden: true`; the rule editor
  explains hidden lines in all 24 locales.


- **Stored configs are masked for every driver.** Every config pull now
  replaces known secret values with `<redacted>` before the config is
  hashed, stored or checked by compliance rules: IOS-style SNMP
  communities, `username` and `enable` secrets and passwords, TACACS+/
  RADIUS keys, `key-string`, pre-shared keys, NTP authentication keys and
  PEM private-key blocks for all drivers, plus Gaia SNMP communities and
  user passwords, FortiOS `psksecret`, `passwd` and certificate blocks,
  and RouterOS SNMP community names and SNMPv3 passwords. In 0.4.0 only
  Gaia password hashes and FortiOS `ENC` values were masked. The keyword
  and the line stay; factory defaults (`public`, `private`, `cisco`,
  `admin`, `password`, `secret`) are never masked so the compliance packs
  still flag them.
- **Stored data is re-masked in place.** On first start the worker masks
  every stored revision and compliance finding once (no new revision, no
  notification, one `config.remask` audit row with counts) and the
  compliance findings re-evaluate. `python -m app.cli remask-configs`
  runs the same job by hand.
- **Config text needs `config:read`.** Opening a stored revision or a
  diff now requires the new `config:read` permission, held by
  Contributor, Operator and Administrator but not Viewer. The revision
  list, pull status, host-key state and findings stay readable at
  `data:read`. `config:read` is a new API token scope; existing tokens do
  not carry it.
- Backup files written before 0.4.1 are **not** rewritten and still hold
  unmasked config text. Delete or re-encrypt any you have handed out.
