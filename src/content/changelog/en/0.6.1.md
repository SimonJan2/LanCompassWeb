### Fixed

- **Active Directory sync names and links the addresses its DNS zones
  describe.** An A, AAAA or PTR record naming a computer now links that
  address to the computer's device, and fills an empty hostname on any
  address, not only on the ones the sync created. On an address a scan,
  a person or another source owns, both wait in the sync's plan as
  conflicts to take; a name already set is never changed, and an address
  two computers' names claim links to neither. On a network the scanner
  already covered, the first sync after the upgrade can list one such
  conflict per unnamed address.
- **Subnets, VLANs and Inventory scroll in one region again.** A page of
  more than 40 rows drew two scrollbars inside the table, and scrolling the
  inner one past the first screen showed an empty table that never ended:
  the rows are drawn for the region the list watches, which was not the one
  that scrolled. The header row still stays in view.
- **The workbook import says which VRF it uses.** The preview and the
  commit report have a row for each VRF: in the Global mode one row (the
  Global VRF, new or existing — every site sheet lands in it), with a VRF
  per site one row beside each site. Before, no row named a VRF, and in the
  Global mode a commit that created none looked like a failure. The wizard
  also keeps the VRF mode when it resumes an import.
- **A sheet that lists one kind of device across sites is split by
  address.** A site sheet where no address block holds half the rows and
  the rows reach five or more sites (a PRINTERS sheet: a printer at each
  site) puts each row at the site of its own block, or at the site whose own
  sheet lists that address, instead of every row at one site. The sheet
  says so in its warnings. On Network_Address.xlsx the same network under
  two sites fell from 34 pairs to 7.
