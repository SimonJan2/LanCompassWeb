# NetBox

NetBox הוא ה־IPAM/DCIM שרוב החנויות כבר מריצות. יש שתי דרכים שהנתונים
שלו מגיעים ל־⁦LanCompass⁩:

- **ייבוא קובץ** (הגדרות → ייבוא) — מעבר חד־פעמי של CSV/ZIP ליום שבו
  עוזבים את NetBox. ראו [ייבוא](/he/docs/import/).
- **ה־connector הזה** — שיקוף חי: בקשות `GET` מאומתות־`Token` מעל ה־
  REST API, המתיישבות באותה תוכנית סנכרון שכל connector מזין. מריצים
  את השניים זה לצד זה, מתיישבים ב־UI, עוברים כשמשתכנעים.

כל בקשה היא `GET` מול `/api/`:

    GET /api/dcim/sites/          -> אתרים + רשימת סימון ההיקף
    GET /api/ipam/vrfs/           -> פיענוח מזהה VRF — רק כשההיקף
                                     מנקוב VRF
    GET /api/dcim/devices/        -> מכשירים + מפת מכשיר→אתר
    GET /api/ipam/prefixes/       -> subnets
    GET /api/ipam/ip-addresses/   -> כתובות

**GET-only הוא מבני**: תעבורת ה־connector לא יכולה לשלוח שאינו־GET —
אסימון עם הרשאות כתיבה עדיין לא יכול לכתוב דרכו. קריאה־בלבד היא הקוד, לא
תקוות הרשאה.

## תפקיד לקריאה בלבד

*נבדק מול ⁦NetBox 4.4⁩ (המעבדה) ומול אסימוני ⁦v2⁩ של ⁦4.5⁩.*

1. *⁦Admin⁩* ← *⁦Users⁩* ← הוסיפו את `lancompass`; *⁦Groups⁩* ← `lancompass-readers` עם הרשאות אובייקט *⁦view⁩* על `dcim.site`, `dcim.device`, `ipam.prefix`, `ipam.ipaddress`, `ipam.vrf`.
2. *⁦Admin⁩* ← *⁦API Tokens⁩* ← *⁦Add⁩* עבור `lancompass`, **⁦Write enabled⁩** כבוי; אפשר גם להגביל את הכתובות המותרות לשרת ⁦LanCompass⁩.
3. העתיקו את האסימון. אסימון ⁦v2⁩ של ⁦NetBox 4.5⁩ (`nbt_…`) נשלח כ־`Authorization: Bearer`, וישן יותר כ־`Authorization: Token` — הדביקו אותו כפי שהוצג.

**מה ⁦LanCompass⁩ קוראת:** `GET /api/status/`, אתרים, מכשירים, קידומות וכתובות ⁦IP⁩ — ⁦GET⁩ בלבד.

## לפני שמתחילים

- **NetBox 3.x או 4.x** — שמות שדות שנדדו בין הגרסאות הגדולות
  (`role`/`device_role`, `site`/`scope`, סטטוסי `{value,label}`) נקראים
  כולם בסובלנות; שדה חסר הוא פרט שירד, אף פעם לא קריסה.
- **הגעה ב־TCP/443** מ־⁦LanCompass⁩ ל־NetBox (או איזה פורט שה־reverse proxy
  שלכם מציג).
- **אסימון API** — תפריט המשתמש ← **API Tokens**. סט הרשאות קריאה־בלבד
  הוא כל מה שה־connector יכול להשתמש בו בכל מקרה.

## שלב 1 — הוספת המקור

הגדרות → אינטגרציות → **מקור חדש** → kind **NetBox**, כתובת בסיס
`https://netbox.example.com` (כתובת עמוד הפתיחה — `/api/…` מתווסף
בשבילכם), האסימון בשדה **API token**, **בדיקה וגילוי**.

שורת הבדיקה מדווחת את גרסת NetBox (מכותרת התשובה `API-Version`) בתוספת
ספירות של מה שהאסימון רואה, ורשימת סימון ההיקף קוראת **אתרים** — שמות
אתרים שהתגלו במשיכה.

## היקף — מה השדות נוחתים בתורו

| שדה               | נשלח כ               | הערות                                  |
| ----------------- | -------------------- | -------------------------------------- |
| **VRF של NetBox** | `?vrf_id=`/`?vrf=`   | שם, RD ‏(`65000:100`), או id — נפענח מול טבלת ה־VRF שנשלפה; ערך שלא נפענח עובר מילולית (יכול להיות RD שאסימון מוגבל לא יכול לרשום). |
| **‏slug אתר**      | `?site=`             | ה*slug*, לא שם התצוגה — prefixes בלבד. |
| **רשימת סימון אתרים** | איחוד `?site=`    | *שמות* אתרים הנפענחים ל־slugs — מתאחדים עם שדה ה־slug. |
| **סטטוס אובייקט** | `?status=`           | prefixes + כתובות IP; `active` ברירת המחדל, `any` מוריד את המסנן. ערך שסוג אובייקט לא מכיר (למשל `dhcp` על prefixes) נותן קטע ריק, לא שגיאה. |
| **תחומי ניתוב** | (התוכנית)           | כל ⁦VRF⁩ של NetBox (ו־`global`, הטבלה הגלובלית של NetBox) ← טבלת ה־⁦VRF⁩ ב־⁦LanCompass⁩ שהקידומות והכתובות שלו נכנסות אליה. הבדיקה מציגה אותם בשלב פרטי ההתחברות. |

היקף אתר מצמצם prefixes בצד־שרת; מכשירים וכתובות IP מצטמצמים בצד־לקוח —
ל־`/ipam/ip-addresses/` אין מסנן אתר בכלל, ולכן כתובת IP מיוחסת דרך
`assigned_object.device` ← מפת המכשירים. שורות שלא ניתן לייחס נשמרות:
לא ניתן לייחס, לעולם לא נזרק.

## מה הוא מייבא

| אובייקט NetBox                   | אובייקט ⁦LanCompass⁩                        |
| -------------------------------- | -------------------------------------- |
| `dcim/sites`                     | אתרים                                  |
| `ipam/prefixes` (שאינם container) | Subnets — שם האתר רוכב להתאמת אתרים   |
| `ipam/ip-addresses`              | כתובות — ה־mask מוסר, `dns_name` ← hostname, הסטטוס של NetBox נשמר: `active` ← פעילה, `reserved` ← שמורה, `dhcp` ← ⁦DHCP⁩, `deprecated` ← לא מקוונת |
| `dcim/devices`                   | מכשירים — יצרן/דגם מ־`device_type`, תפקיד ← `device_type`, כתובות IP ראשיות כ־`addresses` |

בפעם הבאה כל שורה מותאמת לפי המזהה שלה ב־NetBox, כך שאובייקט ששינה את שמו
נשאר שורה אחת ([אובייקט אחד, שורה אחת](/he/docs/integrations/)).

### תחומי ניתוב — מפת ה־⁦VRF⁩

ב־NetBox אותה רשת משנה יכולה להופיע בשתי טבלאות ⁦VRF⁩ (‏`172.29.10.0/24`
גם ב־*Corp* וגם ב־*Tenant-B*). ⁦LanCompass⁩ שומר אותן בנפרד: בשלב פרטי
ההתחברות של המקור, הבדיקה מציגה את טבלאות ה־⁦VRF⁩ של NetBox תחת **תחומי
ניתוב**, ולכל אחת בוחרים טבלת ⁦VRF⁩ ב־⁦LanCompass⁩ ב־**ממופה ל־⁦VRF⁩**.

- טבלה אחת ובלי מפה — הכול נכנס ל־⁦VRF⁩ של המקור, כמו קודם.
- טבלה ממופה — הקידומות והכתובות שלה מותאמות ונוצרות רק בטבלה הזו, כך
  שכל טבלה שומרת את ה־`/24` שלה ואת ה־`.20` שלה.
- שתי טבלאות או יותר ואחת לא ממופה — השורות שלה ממתינות בתוכנית עם ההודעה
  "מפו את Tenant-B ל־⁦VRF⁩"; שום דבר לא מתמזג לטבלה אחרת.

### מה לא מיובא כאובייקט

ל־⁦LanCompass⁩ אין אובייקט עבור **דיירים**, **אזורים** ו**מיקומים** של
NetBox. הם נשמרים כמאפיינים של השורות שמזכירות אותם (האזור והדייר של אתר,
המיקום של מכשיר), והתוכנית אומרת זאת: "לא יובאו כאובייקטים: שני דיירים,
שני אזורים, מיקום אחד — נשמרו כמאפיינים". שום דבר ש־NetBox שולח לא נזרק
בלי מילה.

## הסתייגויות

- **קידומות container מושמטות** — לדקדוק התוכנית אין יצירת container,
  והשורה רק הייתה מתנגשת עם הבנים שלה בכל סנכרון.
- **דילוגים כנים**: `/dcim/interfaces/`, `/ipam/ip-ranges/`, VLANים,
  VMים, tenancy ו־aggregates לא נשלפים — אין מקטע תוכנית שצורך אותם.
  טווחי IP בפרט הם בצורת מאגר־DHCP ב־⁦LanCompass⁩; טווח NetBox עם תפקיד
  אחר היה משקר.
- **‏VRF ברמת השורה עובר דרך המפה** — כשיש שתי טבלאות ⁦VRF⁩ של NetBox או
  יותר, מפו כל אחת לטבלת ⁦VRF⁩ ב־⁦LanCompass⁩ (למעלה); טבלה שלא מופתה
  ממתינה בתוכנית.
- **העימוד חסום** — `?limit=500&offset=` תוך כיבוד offset הסמן `next`
  (כתובת ה־`next` המוחלטת אף פעם לא נעקבת — הלקוח מוצמד למארח ה־NetBox
  שלכם), 40 עמודים לנקודת קצה, תקרת שורות קשיחה לכל מקטע; גלישה היא
  רשומת חסימה־עם־שגיאה, אף פעם לא קטיעה שקטה.
- **משיכות חלקיות מדווחות** — נקודת קצה ש־404 או נכשלת (NetBox ישן בלי
  `/vrfs/`, אובייקט שהאסימון לא רואה) נוחתת כרשומת שגיאה; כל נקודת קצה
  אחרת עדיין מייבאת.

## המעבר ב־CSV (ייבוא קובץ)

המיגרציה החד־פעמית היא **הגדרות → ייבוא → ייצוא NetBox** — קובץ ZIP
של ייצואי CSV מ־NetBox, או אותם קבצים שנזרקים פנימה אחד־אחד. ייצואים
מ־NetBox 3.6–3.7, 4.0–4.1 ו־4.2+‎ נקראים; שינויי כותרות בין גרסאות
מנורמלים במקום להידחות:

- `device_role` ‏(4.x)‏ ו־`role` ‏(3.x)‏ שניהם ממופים לתפקיד המכשיר.
- `site` בקידומת ‏(≤4.1)‏ וזוג `scope_type`/`scope` ‏(4.2+)‏ שניהם
  מקשרים קידומת לאתר.
- שיוכי IP על `virtual_machine`/`vminterface` ‏(3.x)‏ ו־
  `assigned_object_*` ‏(4.x)‏ שניהם נפתרים.
- `vminterfaces.csv`, `vm_interfaces.csv` ו־
  `virtual_machine_interfaces.csv` הם כולם אובייקט ממשקי־VM.

### מה ממופה לאן

| ייצוא NetBox                        | ⁦LanCompass⁩ |
| ----------------------------------- | ---------- |
| `sites`                             | אתרים — שמות region/site-group מתקפלים ל־custom fields |
| `rack_groups`, `racks`              | קבוצות ארונות וארונות — שם location רוכב על ה־room של הארון |
| `device_types` + `interface_templates` | סוגי מכשירים, עם פריסת היציאות |
| `devices`                           | מכשירים — סוג, תפקיד, platform ו־tenant נפתרים לאובייקטים ול־custom fields; כתובות IP ראשיות רוכבות |
| `virtual_machines`                  | VMים — cluster, אתר ו־tenant נפתרים באותו אופן |
| `interfaces`, `vminterfaces`        | ממשקים מחווטים למכשיר או ל־VM שלהם |
| `cables`                            | כבלים — נקודת קצה מוצהרת שלא נפתרת היא **התנגשות** (הטענה הטופולוגית נאמרה; היא לא נזרקת בשקט) |
| `vrfs`                              | VRFים — עמודת VRF ריקה מצטרפת ל־VRF הגלובלי; VRF *בשם* שלא קיים הוא **שגיאה**, אף פעם לא נפילה שקטה ל־fallback |
| `vlan_groups`, `vlans`              | קבוצות VLAN ו־VLANים, כולל היקף |
| `prefixes`                          | רשתות משנה — site/scope נפתר; tenant ו־region רשומים בפירוט השורה כי למודל אין custom fields |
| `ip_ranges`                         | טווחי IP — נקודות קצה עם mask ‏(`10.0.0.1/24`)‏ מנורמלות; כתובת סטטית בתוך טווח נחתמת עליו ‏(`pool_override`)‏ |
| `ip_addresses`                      | כתובות — VRF, סטטוס וקישור ממשק המכשיר/VM |
| `wireless_lans`                     | רשתות אלחוטיות — רק היקף אתר מיובא; היקפים אחרים מדווחים במקום לנחש |

### מדווח אבל לא מיובא

ל־`clusters`, `regions`, `site_groups`, `locations`, `tenants`,
`manufacturers`, `device_roles`, `platforms`, `cluster_types`,
`cluster_groups`, `wireless_links`, `tenant_groups` ו־
`wireless_lan_groups` אין אובייקט ⁦LanCompass⁩ — השורות מופיעות
בטבלת *לא־ממולדות* של דוח הכיסוי עם הספירות והסיבה, והנתונים
מתקפלים לשורות הממולדות שמפנות אליהן היכן שיש שדה (יצרן על סוג
המכשיר, cluster על ה־VM, tenant על custom fields). קובץ שהכותרות שלו
לא תואמות אף אובייקט NetBox רשום באותו אופן — דבר לא נזרק בשקט.

### קריאת דוח הכיסוי

לאשף הייבוא יש שלב **כיסוי** בין תצוגה מקדימה לביצוע
‏(`GET /api/v1/imports/{batch}/netbox-coverage`, CSV באותו נתיב ועוד
`.csv`)‏. לכל אובייקט ממולד: שורות CSV שנראו, ואז ספירות נוצר /
עודכן / דולג / התנגשות / שגיאה — דילוגים נושאים היסטוגרמת סיבות
(`identical`, `already exists`, …) כך שאחוז דילוג מסביר את עצמו.
לפני commit הדוח מתאר את התוכנית; אחרי commit הוא כיסוי ה־commit
השמור — התג **מתוכנן** / **בוצע** אומר איזה מהם אתם קוראים.

ייבוא חוזר של ייצוא ששונה הוא מעבר עדכון: כל שורת `update` מציגה
diff *לפני ← אחרי* ברמת־שדה בפירוט שלה, כך שהרצה חוזרת ניתנת לביקורת
במקום להיות עיוורת.

| הודעה | מה היא אומרת ← מה עושים |
|---|---|
| *…: האימות נכשל (403)* | האסימון שגוי, פג או מוגבל לכתובות אחרות ← הדביקו אסימון חדש ובדקו את הכתובות המותרות שלו |
| *…: לא נמצא* | כתובת הבסיס אינה של ⁦NetBox⁩ (נתיב חסר או מיותר) ← השתמשו בכתובת שבה פותחים את ⁦NetBox⁩ |
| *יש למפות את … ל־⁦VRF⁩ — … ממתינה עד שיהיה לו* | ב־⁦NetBox⁩ יש ⁦VRF⁩ שאין לו מיפוי ב־⁦LanCompass⁩ ← מפו אותו בחלון המקור |
| *⁦tls⁩: התעודה של … אינה התעודה המוצמדת* | התעודה של ⁦NetBox⁩ השתנתה ← השוו את טביעת האצבע שלה, ואז *לסמוך על התעודה הזו* בבדיקה |
