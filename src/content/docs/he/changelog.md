# יומן שינויים

כל יצירה, עדכון ומחיקה מתועדים עם **actor, חותמת זמן ו־diffs לפני/אחרי
ברמת שדה**. שום דבר לא משתנה בשקט.

## היומן הגלובלי

`/changelog` מציג כל שינוי במערכת, החדש ביותר קודם:

| עמודה | משמעות |
|---|---|
| **Timestamp** | מתי זה קרה |
| **Actor** | מי עשה את זה (שם משתמש, או ה־worker לשינויים מונעי-סריקה) |
| **Action** | `create` / `update` / `delete` |
| **Object** | סוג + repr קריא (`Tag "core"`, `10.0.0.5`…) |
| **Changes** | לפני → אחרי לכל שדה |

עמודת הסוג והמסנן שלה מציגים כל אובייקט בשפה שלכם ("כלל תאימות", ולא
‏`ComplianceRule`), ושינוי מציג את השדה שלו עם תווית ("אתר" במקום
‏`site_id`); שדה בלי תווית מוצג בשם העמודה שלו בגופן קוד. קובצי הייצוא
שומרים את השמות כפי שהם מאוחסנים.

פעולות bulk כותבות רשומה אחת לכל שורה מושפעת — מחיקת bulk של 50 כתובות
מייצרת 50 רשומות עקובות, לא אירוע אטום אחד.

**מתאריך** ו**עד תאריך** מעל הרשימה מצמצמים אותה לטווח תאריכים — ימים
קלנדריים באזור הזמן של התצוגה במערכת, כולל שני הקצוות — ו**ייצוא** כותב
את הטווח הזה (בשם הקובץ מופיע `-<from>_<to>`), כך שהרבעון של המבקר הוא
סינון אחד וייצוא אחד. הטווח נשמר בכתובת של הדף
(`/changelog?since=2026-07-01&until=2026-09-30`); דוח לתקופה מקשר לכאן עם
הימים שלו.

## ייצוא השביל

תפריט ה**ייצוא** ב־`/changelog` מוריד את **כל שביל הביקורת** שתואם למסננים
הפעילים של הדף, מהישן לחדש — השינוי האחרון בסוף — בלי קשר למספר השורות.
אותו ⁦URL⁩ משרת גם סקריפטים ואסימונים:

```
GET /api/v1/changelog/export?format=csv|jsonl
    &object_type=<t[,t…]>&object_id=<id>&action=<a[,a…]>&actor=<a[,a…]>
    &q=<text>&since=<iso>&until=<iso>&after_id=<id>&limit=<n>&all=true
```

- **`all=true`** — מה שתפריט הייצוא מבקש: כל השורות התואמות בקובץ אחד,
  שנקראות בשרת ⁦50,000⁩ בכל פעם (`limit` לא חל). בלעדיו הייצוא עונה
  בעמודים, כמו שמתואר בהמשך.

- **CSV** — `ts,actor,action,object_type,object_id,object_repr,changes`
  (changes כמחרוזת JSON; BOM של UTF-8 כדי ש־Excel יציג reprs בעברית).
- **JSONL** — אובייקט JSON אחד בכל שורה עם אותם שדות.
- המסננים משקפים את ה־list endpoint: סטים מופרדים-פסיקים ל־
  `object_type`/`action`/`actor` (ערך שמכיל פסיק אפשר לציין במרכאות
  בסגנון RFC-4180 כ־`"doe,john"`), `q` כתת-מחרוזת מילולית על
  repr/סוג/actor — לעולם לא תו-כללי — ו־`since`/`until` תוחמים את חותמת
  הזמן (ערכים נאיביים נקראים כ־UTC).
- בטוח לגיליונות: תא שהערך שלו היה מפוענח כנוסחה (`=`, `+`, `-`, `@`)
  מיוצא מנוטרל עם `'` מובילה.
- בלי `all=true` השורות זורמות ישן-קודם לפי `id`, חתוכות ב־**50,000 לבקשה**
  — עמוד מלא מחזיר כותרת `X-Next-Cursor` ו־`X-Truncated: true`; המשיכו עם
  `?after_id=<אותו id>`. זה סמן,
  אף פעם לא OFFSET לתוך טבלה חיה, כך שהייצוא לא יכול לדלג או לחזור תחת
  כתיבות מקבילות.
- דורש `data:read` — אסימון API עם `data:read` יכול למשוך את הפיד ישירות;
  שום דבר אחר באימות לא משתנה.
- שורות שה־diffs שלהן מכילות שם שדה שנראה-רגיש מיוצאות עם ה־payload
  מושתק כ־`[redacted]` — שורה שהוזנה ידנית לא יכולה לשלוח סוד החוצה דרך
  הייצוא.

## השביל כפיד syslog

ערוץ התראות syslog שסומן **שידור יומן הביקורת** משדר כל שורת יומן חדשה
לקולקטור שלו כשורת `AUDIT` — אותו שביל, כפיד חי ש־SIEM יכול להירשם אליו.
ראו [ניטור ← שידור ביקורת](/he/docs/monitoring/#audit-forward).

## היסטוריה לכל אובייקט

אותם נתונים מצומצמים לאובייקט אחד:

- **כפתור History** בפעולות שורה ברשימות ישויות.
- **מגירת IP** — שביל הביקורת של הכתובת לצד השדות שלה.

## כיסוי

יומן השינויים תופס עריכות UI, כתיבות API, פעולות bulk, מחיקות שמדורגות
להקצאות תגיות, דריסות הגדרות ושינויי סטטוס מונעי-סורק (active ↔ offline,
אישורי discovery).

## שמירה

אדמינים יכולים לטהר את היומן מ־**Settings → Data & Maintenance** — פעולה
שהיא עצמה מתועדת.
