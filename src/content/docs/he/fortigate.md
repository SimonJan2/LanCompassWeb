# FortiGate

FortiGate הוא ההמשך הנקי של חומת האש: אסימון API אחד, קריאות `GET` טהורות
מול נקודות ה־monitor וההגדרות של FortiOS. הקונקטור שולף את המספר הסידורי
של התיבה ואת גרסת ה־⁦FortiOS⁩ שלה, את רשימת הממשקים (כולל VLANים
ו־SVIs), השכרות DHCP, טבלת ה־ARP ומלאי המכשירים — כל מה ש־⁦LanCompass⁩
צריך כדי לתאר את המקטעים המנותבים שהתיבה רואה — ופעם ביום, אם מבקשים,
גם את אובייקטי הכתובות, המדיניות וה־⁦VIP⁩, כך שהדף של רשת מציג את
המדיניות שנוגעת בה.

במערכות מרובות־VDOM, הטבלאות של כל VDOM יושבות תחת `?vdom=<name>` — אחרי
**Test & discover** ראשון, דיאלוג הסקופ מציג את ה־VDOMים שנמצאו; סמנו את
אלה שצריך לקרוא. כל ⁦VDOM⁩ הוא טבלת ניתוב משלו: מפו אותו פעם אחת ל־⁦VRF⁩
של ⁦LanCompass⁩ (בהמשך).

## תפקיד לקריאה בלבד

*נבדק מול ⁦FortiOS 8.0⁩ ו־⁦7.6⁩ (הסימולטור של המעבדה).*

1. *⁦System⁩* ← *⁦Admin Profiles⁩* ← *⁦Create New⁩* `lancompass-ro`: כל קבוצת הרשאות **⁦Read⁩**, אף אחת לא *⁦Read/Write⁩*. ב־⁦CLI⁩: `config system accprofile`, `edit "lancompass-ro"`, `set sysgrp read`, `set netgrp read`, `set fwgrp read`, `set authgrp read`, `end`.
2. *⁦System⁩* ← *⁦Administrators⁩* ← *⁦Create New⁩* ← **⁦REST API Admin⁩** ← השם `lancompass`, הפרופיל `lancompass-ro`, **⁦Trusted Hosts⁩** — שרת ⁦LanCompass⁩ כ־/32 (⁦FortiOS⁩ מסרב ל־`0.0.0.0/0`); בקופסה עם כמה ⁦VDOM⁩ סמנו את אלה שצריך לקרוא.
3. העתיקו את האסימון — ⁦FortiOS⁩ מציג אותו פעם אחת — והדביקו אותו כמפתח של המקור.
4. רשימת ה־⁦Trusted Hosts⁩ של המנהל עצמו חלה גם על קריאות ⁦API⁩: שמרו עליה ועל הרשימה של משתמש ה־⁦API⁩ מתואמות.

**מה ⁦LanCompass⁩ קוראת:** `monitor/system/status`, `cmdb/system/vdom`, הממשקים (`monitor` ו־`cmdb/system/interface`), `monitor/system/dhcp`, `arp`, `ipv6-neighbor-cache`, טבלת המכשירים, ופעם ביום, אם סומן, `cmdb/firewall/address`, `address6`, `addrgrp`, `policy`, `vip` — ⁦GET⁩ בלבד.

## לפני שמתחילים

- **FortiOS 6.x ומעלה** — שכבת ה־REST `/api/v2` דולקת כברירת מחדל.
  ⁦FortiOS 8.0⁩ ו־⁦7.6⁩ נתמכות; ⁦7.4⁩ ו־⁦7.2⁩ — במידת האפשר.
- **HTTPS** — FortiOS מחייב TLS על ה־API. השאירו *verify TLS* דולק עם
  תעודה אמיתית, או כבוי לתעודת ה־self-signed מהמפעל.
- **הגעה ב־TCP/443** ממארח ה־⁦LanCompass⁩ ל־FortiGate.
- **בערך עשר דקות** ב־GUI של ה־FortiGate.

## שלב 1 — יצירת REST API admin

1. **⁦System⁩ ← ⁦Admin Profiles⁩ ← ⁦Create New⁩** `lancompass-ro`: כל
   קבוצה **⁦Read⁩**, אף אחת לא *⁦Read/Write⁩* (ב־CLI: `config system accprofile`
   ← `edit "lancompass-ro"` ← `set sysgrp read`, `set netgrp read`,
   `set fwgrp read`, `set loggrp read` …). קריאת המדיניות דורשת הרשאת
   קריאה ל־**⁦Firewall⁩** (`fwgrp`).
2. **⁦System⁩ ← ⁦Administrators⁩ ← ⁦Create New⁩ ← ⁦REST API Admin⁩**: שם
   משתמש כמו `lancompass-reader`, הפרופיל `lancompass-ro`.
3. הגדירו את **⁦Trusted Hosts⁩** לכתובת מארח ה־⁦LanCompass⁩ כ־⁦/32⁩ —
   ⁦FortiOS⁩ דוחה `0.0.0.0/0`. רשימת המארחים המהימנים של המנהל עצמו חלה גם
   על קריאות ⁦API⁩: שמרו על התאמה בין שתי הרשימות. מארח שמחוץ להן נדחה
   ב־⁦403⁩, ו־*Test* אומר *רשימת המארחים המהימנים של מנהל ה־⁦REST⁩ אינה
   כוללת את השרת הזה (…)*, עם הכתובת שחומת האש ראתה.
4. **⁦Multi-VDOM⁩**: סמנו את ה־⁦VDOMs⁩ ש־⁦LanCompass⁩ צריכה לקרוא.
5. שמרו. הקונסולה מציגה את האסימון **פעם אחת** — העתיקו אותו ישר לשדה
   **API token** של המקור; אין צפייה שנייה.

הקונקטור שולח אותו כ־`Authorization: Bearer <token>` — בכותרת, אף פעם
לא בכתובת.

## שלב 2 — הוספת המקור

Settings → Integrations → **New source** → סוג **FortiGate**, כתובת בסיס
`https://<fortigate>`, מדביקים את האסימון, מריצים **Test & discover**.
התגובה מזהה את התיבה (גרסת FortiOS + hostname) וסופרת מה היא רואה;
תווית הסקופ נקראת **VDOMים** כשהחומה מריצה יותר מאחד.

## ⁦VDOMs⁩ ומיפוי תחומי הניתוב

⁦VDOM⁩ הוא טבלת ניתוב משלו: בשני ⁦VDOMs⁩ יכול להיות `172.29.10.0/24`,
ומארח בכל אחד מהם הוא שני מארחים שונים. ⁦LanCompass⁩ שומרת על ההפרדה:

- **⁦VDOM⁩ אחד** (או אף אחד) — הרשתות והכתובות שלו נכנסות ל־⁦VRF⁩ של
  המקור, כמו תמיד.
- **שני ⁦VDOMs⁩ או יותר** — תחת **תחומי ניתוב** בשלב האישורים, *Test*
  מציג את ה־⁦VDOMs⁩ שמצא; בחרו לכל אחד ⁦VRF⁩ של ⁦LanCompass⁩, פעם אחת.
  עד שממפים ⁦VDOM⁩, השורות שלו ממתינות בתוכנית כ־**מיפוי … ל־⁦VRF⁩** —
  ולעולם אינן מתמזגות לטבלה של ⁦VDOM⁩ אחר.

כל ממשק, רשת, השכרה, שורת ⁦ARP⁩ ושורה מטבלת המכשירים שומרים על ה־⁦VDOM⁩
שלהם: אותה כתובת בשני ⁦VDOMs⁩ הופכת לשתי כתובות בשני ⁦VRFs⁩.

## המדיניות וה־⁦VIP⁩ (פעם ביום)

סמנו במקור **לקרוא את המדיניות ואת ה־⁦VIP⁩ (פעם ביום)** כדי לקרוא פעם
ביום, לכל ⁦VDOM⁩, את `cmdb/firewall/address`, `address6`, `addrgrp`,
`policy` ו־`vip` (בקריאות ⁦GET⁩ בלבד):

- אובייקט כתובת מסוג `ipmask` או `iprange` הופך לכתובות שלו, קבוצה —
  לחברים שלה (גם קבוצות בתוך קבוצות), `all` — ל־**⁦Any⁩**; אובייקט `fqdn`
  נשאר שם;
- כתובות המקור והיעד של כל מדיניות הופכות לשורות בטבלת החוקים (המספר
  שלה, השם, הפעולה, אם היא פעילה, וה־⁦VDOM⁩ שלה כשכבה);
- כל ⁦VIP⁩ הוא שורת ⁦NAT⁩: ה־`extip` שלו הוא היעד המקורי וה־`mappedip` —
  היעד המתורגם, כך ששירות מפורסם נמצא גם לפי הכתובת החיצונית וגם לפי
  הפנימית; מדיניות שמציינת את ה־⁦VIP⁩ נוגעת בשתיהן.

הדף של רשת מציג אז **חוקים שנוגעים ב־…** עם המדיניות של ה־⁦FortiGate⁩
לצד החוקים של ⁦Check Point⁩, והחוקים של ⁦VDOM⁩ מופיעים רק ברשתות של
ה־⁦VRF⁩ שאליו הוא ממופה. התדירות: הגדרות ← אינטגרציות ← **קריאת חוקי
חומת האש בכל (דקות)** — פעם ביום כברירת מחדל, ולעולם לא לפי לוח הזמנים
של הסנכרון. פרופילי אבטחה, חוקי ⁦SD-WAN⁩ ומדיניות ⁦local-in⁩ אינם נקראים.

## מה מיובא

| נתוני FortiOS                                    | אובייקט ⁦LanCompass⁩                        |
| ------------------------------------------------ | ------------------------------------- |
| מצב המערכת (`monitor/system/status`)              | המספר הסידורי וגרסת ה־⁦FortiOS⁩ של חומת האש |
| תגי VLAN על ממשקים (`cmdb` כגיבוי ל־VIDים)       | VLANים                                |
| שיוכי IP על ממשקים                               | Subnets (קידומות) + ה־IP של ה־gateway, ב־⁦VRF⁩ של ה־⁦VDOM⁩ |
| השכרות DHCP (`monitor/system/dhcp`)              | כתובות — `reserved` לשריונים          |
| טבלת ARP (`monitor/system/arp`)                  | כתובות (`source=integration`)         |
| מלאי מכשירים (`monitor/user/device/query`)        | מכשירים עם last-seen                   |
| חומת האש עצמה                                    | מכשיר (`source=integration`) — מספר סידורי, `FortiGate <version>` |
| אובייקטי כתובות, מדיניות ו־⁦VIP⁩ (לפי בחירה, פעם ביום) | לוח החוקים בדף של רשת ובמגירה של כתובת |

שריוני DHCP מיובאים כ־`reserved`; השכרות רגילות ורשומות ARP כ־`discovered`.
התשובה של ניטור הממשקים נקראת בין ש־⁦FortiOS⁩ שולח רשימה ובין שהוא שולח
אובייקט לפי שם הממשק.

## סייגים

- **VDOMים**: הקונקטור קורא כל VDOM שהאסימון מגיע אליו; רשימת הסקופ מצמצמת.
  REST admin הקשור ל־VDOM אחד רואה רק את הטבלאות שלו — זו צורת ההרשאות
  המינימלית, לא באג.
- **מזהי VLAN** על ממשקים מתויגים מגיעים מקריאת ה־`cmdb`; כשרק מבט
  ה־monitor עונה, ה־subnet של הממשק עדיין מיובא אבל ה־VID עלול לחסור.
- **תחלופת ARP**: FortiOS מנקה את הטבלה מהר, ולכן ספירות יורדות בין
  סריקות. צפוי — ה־diff של ה־apply מספר את הסיפור האמיתי.
- **⁦FortiManager⁩** הוא ⁦API⁩ אחר ואינו נקרא.
