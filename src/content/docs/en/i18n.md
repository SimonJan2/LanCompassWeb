# Languages & RTL

LanCompass has 24 interface languages in three tiers:

- **Complete — `en`, `he`.** Every string translated and reviewed; the gates hold them at zero English leaks.
- **Partial — `ar`.** About a quarter of the interface; the docs are translated.
- **Core screens — the other 21.** Navigation and common actions; the rest shows English. The docs are translated for nine of them (`ru`, `fr`, `de`, `es`, `pt`, `it`, `nl`, `pl`, `zh`), and a chapter that changed after its translation says so.

The language picker sorts the complete languages first, then the
partial one, then the core screens, and shows under each language its
tier and how much of the interface it translates (measured by
`npm run check:i18n -- --write` into `src/i18n/coverage.json`). A language
cannot fall below its tier: `check:i18n` fails when a complete language
gains an English value, when `ar` drops below its coverage floor, or
when a core-screens language loses a translated navigation key. Plurals
follow each locale's CLDR categories, and `he` is held to its full set
(one/two/other).

In Arabic and Persian an English fallback sits inside a left-to-right
isolate, so its punctuation and numbers stay at its own end of the line.

## Picking a language

- **Your preference:** Settings → Appearance → **Language**. Stored per
  browser in localStorage (same mechanism as theme and density), applied
  instantly — no reload, no URL change.
- **Install default:** admins set **Settings → Features → Language &
  region → `default_language`**. New browsers and users who haven't
  picked a language see this default.

Resolution order: your preference → install default → English.

Locales are **not** encoded in URLs — `/prefixes` is the same deep link in
every language. Dictionaries for non-English locales load lazily on first
select (a separate chunk, then cached); English ships in the main bundle.
A missing key falls back to the English value, never the raw key name.

## Documentation languages

`en` and `he` are the reviewed reference set. The guides are also
translated into `ar` and nine core-screens languages (`ru`, `fr`, `de`,
`es`, `pt`, `it`, `nl`, `pl`, `zh`); the other twelve languages show the
English article with a "not yet translated" notice instead.

Each translated page records the hash of the English file it was
translated from (`source_sha256` in `manifest.json`), so when an English
article drifts the translation flags itself **stale** on the page — and
`npm run check:docs` fails the build if a translated language's chapter
is missing or still a seed.

## RTL

Hebrew, Arabic (`ar`) and Persian (`fa`) run the whole layout
right-to-left — the sidebar docks right, breadcrumbs mirror, table
columns align to `start`, and dropdowns/dialogs flip via Radix's
direction context. The switch happens on `<html dir>` before first paint
(no layout flash).

What stays left-to-right inside an RTL UI:

- **Technical data** — IPs, CIDRs, MACs, hostnames, serials, VLAN IDs,
  ISO timestamps — rendered in `dir="ltr"` + `unicode-bidi: isolate`
  spans so digits never scatter through RTL sentences.
- **Directional canvases** — rack elevations, the topology map, the
  subnet grid, print views — geometry is physical, so the canvas pins
  `dir="ltr"`; Hebrew labels *inside* nodes still render correctly.
- **Chart time axes** — time runs left to right in every language: a
  dashboard chart's plot is pinned `dir="ltr"`, while the card around it,
  its legend and its tooltip mirror with the UI. Units after numbers
  (`28.2%`) are isolated so they stay with their digits.
- **The mono font** — **IBM Plex Mono** never changes.

Hebrew is set in **IBM Plex Sans Hebrew** (400, 500 and 600) behind IBM Plex Sans; the mono font is **IBM Plex Mono**; Arabic uses **Noto Sans Arabic**.
The faces ship with the product (`frontend/src/fonts/`), so nothing is
fetched from the network. Under the display themes the cyberpunk headings
switch from Rajdhani (which has no Hebrew or Arabic glyphs) to the
product's own face at 600 with no letter-spacing, and under `lang="ar"`
Noto Sans Arabic sits behind the Plex faces. Numbers render as western digits and dates follow `he-IL` conventions
(DD/MM/YYYY, 24h) — standard for Israeli tooling.

## ICU plurals

Messages use ICU syntax — `{count, plural, one{...} other{...}}` — and
each locale carries the branch set its CLDR rules actually resolve:
Hebrew `one/two/other`, Russian and Polish `one/few/many/other`, Arabic
`zero/one/two/few/many/other`, Chinese `other` only. The checker
validates every plural against the locale's CLDR category set, so a
wrong `plural` block fails the build instead of rendering wrong.

## For contributors

- `src/i18n/messages/en.json` is the source of truth — every key lives
  there first.
- `npm run check:i18n` gates the build: key parity across all 24 files,
  ICU parse errors, placeholder parity, CLDR-correct plural categories
  per locale, and a raw-literal denylist on swept components.
- To fix a bad string in a partial or core-screens language, edit
  `src/i18n/messages/<code>.json` directly — keep `{placeholders}` and
  use the locale's CLDR plural branches (`src/i18n/GLOSSARY.md` has the
  shared term choices), then run `npm run check:i18n -- --write` so the
  picker's coverage follows.
- New UI text gets a namespaced key (`<area>.<thing>`) in `en.json` and a
  `t("…")` call — never a raw JSX literal.
- **The Hebrew leak gate.** `npm run check:he-leaks` opens every route in Hebrew and fails when English outside `frontend/scripts/he-allowlist.json` appears; CI runs it on the demo estate in the Survey theme at desktop and phone width.
  Data is never a leak (the names, notes and pages your estate holds, the
  demo estate's content), nor Latin a Hebrew network engineer reads in
  Latin — a protocol, a brand, a typed value; each such class sits in the
  allowlist with its reason and the screens it appears on. A string that
  fails the gate gets a message key, or a class in the allowlist with a
  reason; "hard to translate" is not one.
