# Claims register — what the site says about LanCompass, and where it is true

Every sentence about the product on this site cites a row of this file, and every figure in
the copy appears in the row it cites (`tests/claims.spec.ts`). The rows describe the product's
latest release tag, **`v0.7.0`** (`6d248a18`, 2026-11-06), read at the tag:

```sh
git -C /home/simonj/Documents/github/LanCompass show v0.7.0:<path>
```

"CL" is `CHANGELOG.md` at the tag: its section, then the bullet's bold lead. "Docs" is
`frontend/src/content/docs/en/<file>` at the tag, then the heading. **Since** is the release a
fact first shipped in (0.5.0 folds every release before it). **Pages** says where the site uses
the row; a row no page uses says `unused —` and why.

How to cite: a comment beside the sentence — `// C-MAP-1` in `src/content/copy/en.ts` and
`he.ts`, `{/* C-SEC-3 */}` in `.mdx`. A comment on its own line covers the next line, or the
whole object or array that line opens. The Hebrew copy cites the same ids; this register is not
translated. A claim whose wording is in doubt takes the narrower wording. To strike a row, delete
it: `npm run test` then names every sentence that still cites it.

The figures' captions and notes (`figures` in the copy files, W4) and the "What talks to what"
drawing (`howItRuns`, W4) cite rows the same way. The notes sit on `/product`'s screens, the
drawing on `/security#how-it-runs` and `/product#platform`; the Pages column names them only for
the rows they added (C-INST-12, C-INST-13).

At a release: re-read every row's source at the new tag, change the rows that changed, and update
`src/content/releases.json`.
